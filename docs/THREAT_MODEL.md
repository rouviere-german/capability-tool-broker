# Threat model

Method: STRIDE per trust boundary. Each row maps a threat to the control that addresses it and to
the test, bench script or CI job that shows the control works. `scripts/check_baseline.py` verifies
that every backticked evidence reference exists.

## System and trust boundaries

```mermaid
flowchart LR
    llm[LLM provider<br/>Fake / Replay / Anthropic] -- "TB1: model output is untrusted" --> host
    subgraph host[agent-host]
        planner[planner] -- "offline attenuation" --> sub[sub-agents]
    end
    host -- "TB2: client JWT" --> authority[authority<br/>root key ring, policy]
    host -- "TB3: token + discharges" --> broker[broker<br/>root keys, manifest key,<br/>service credentials]
    host -- "approval request" --> approver[approver<br/>X25519 caveat key]
    human[human reviewer] -- "TB4: review CLI" --> approver
    subgraph backend[internal backend network]
        services[invoices / files / mailer]
        redis[(Redis<br/>counters, nonces, denylist)]
    end
    broker -- "TB5: HMAC-signed requests" --> services
    broker -- "TB7: password-authenticated" --> redis
    authority & approver & broker --> audit[(hash-chained audit logs<br/>+ signed checkpoints)]
    signer[offline manifest signer] -- "TB6: Ed25519-signed manifest" --> broker
```

Assets: the root key ring (authority and broker), the approver's X25519 private key, service
credentials (broker and services), the manifest signing key (offline), client private keys (agent
host), the Redis password and the audit checkpoint keys, capability tokens and discharges (bearer
credentials with narrow authority), broker state (counters, single-use nonces, revocations), the
integrity of effects at the services, audit evidence, and spend (LLM tokens and USD).

Attacker model: a prompt injection fully controls the model's tool calls; a compromised agent host
process can read and modify its own tokens, discharges and state, call every endpoint it can
reach, and use its client private key, so it can request any template the policy grants its client
with parameters of its choosing (E6); a network attacker can observe or replay traffic unless TLS
is terminated in front of the services. The broker and the authority are trusted with the root key
(see ADR 0002). The approver is trusted to show the reviewer the request it approves.

Assumptions: TLS terminates in front of every service in production; the container runtime and the
hosts of the authority and the broker are trusted; the reviewer reads the request shown by the CLI;
the deployment keeps agent hosts off the network that carries Redis and the services, as the
compose file does.
